Built for people who actually ship

Every control below is in the library today, works on mobile, saves to config, and can be locked, cooled down, bound to a key or pinned to the status bar.

Editable dropdowns

Dropdowns whose options the player can type, rename and delete at runtime. The popup follows its anchor instead of the scroll.

Inline editable values

Click a number in any title or description and type a new one. No extra textbox, no modal, no layout jump.

Icons cached to disk

Pull an icon from Lucide, Iconsax, a URL or a Roblox asset. It lands in DeaDx/icons/, is verified by name and content hash, and is overwritten only when it really changed.

Hardened key system

Validity lives in a weak-keyed vault behind an HMAC proof, not a boolean. A guard watches its own methods and trips in about two seconds when one is hooked.

Key+ encrypted delivery

Your server returns the hub encrypted, so there is no true to hook. The secret never leaves your backend — it can even be derived from the key the player typed.

Luarmor built in

One call checks a Luarmor key, maps all 12 status codes to a readable line, and knows which failures are the player's fault and which are yours.

ESP preview cards

A card with a live 3D player on the left and your toggles on the right, so the player sees the ESP before turning it on in the game.

Status bar on the HUD

FPS, ping, time, a custom name, or any component you pin — on top, in a corner, or wherever the player drags it.

Locks and cooldowns

Lock any control with a padlock, a blurred cover and a live 00:05 countdown, then watch it unlock itself.

One file to paste, 79 modules to read

Run build.ps1 and the modules become DeaDx.lua. Nothing is generated by hand, nothing is duplicated.

Icons

Download once. Ever.

Ask for "swords" and DeaDx resolves it through the provider you picked, writes the SVG to DeaDx/icons/swords.svg, stores a content hash beside it, and hands the next call the cached copy in about a millisecond.

If the source file changes, the hash stops matching, the file is overwritten in the background and IconStore.Updated fires. Nothing re-downloads while the hash still matches.

Protection, measured — not promised

Three ways to gate a hub, each tested against the attacks people actually run.

Key system

HMAC vault, not a boolean

Setting _valid = true does nothing — the unlocked state is an HMAC proof held in a weak table keyed by the instance, re-derived on every read. The built-in guard checks its own methods on a timer and locks back down when one is replaced.

Key+

Nothing to hook

Your server answers with the hub itself, encrypted. There is no boolean in the flow, so a hook returns an encrypted blob. Wrong key, expired stamp or forged signature all fail closed, and the secret stays on your backend.

Luarmor

Twelve codes, one line each

The public SDK is downloaded once and cached. Every status code gets a readable message, and DeaDx knows the difference between a bad key (burn an attempt) and a bad script id (your mistake, no attempt burned).

Said plainly: nothing running in the player's executor is unbreakable. getgc can still find the vault, and hooking IsValid works until the guard notices. Key+ is the one that holds, because the script itself never reaches the client until the server decides to send it.
