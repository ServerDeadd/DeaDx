Documentation

Everything DeaDx does, with a copyable example for each one. Nothing here is planned or partial — it is all in the library today.

Install

Two builds, same API. The single file is what you ship; the modular loader is what you use while working on the library itself.

single file — no internal HTTP
local DeaDx = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/ServerDeadd/DeaDx/main/DeaDx.lua"
))()
modular — pulls each module from the repo
local DeaDx = loadstring(game:HttpGet(
    "https://raw.githubusercontent.com/ServerDeadd/DeaDx/main/src/init.luau"
))()
Loading DeaDx twice is safe — the second load unloads the first one. There is no leftover ScreenGui and no duplicated keybind.

Architecture

Every file in src/ is a module that takes import and returns a table. Nothing reaches for a global, nothing requires anything by path, and import memoises, so a module runs once no matter how many others pull it in.

src/Components/MyThing.luau
return function(import)
    local Utility = import("Core/Utility")
    local Widgets = import("Core/Widgets")

    return function(ctx, id, config)
        local base = ctx.Component(ctx, id, config)
        -- build into base.Frame / base.Right
        return base
    end
end

Register it and it becomes Section:AddMyThing(...):

your own component
DeaDx:RegisterComponent("MyThing", function(ctx, id, config)
    local base = DeaDx.Component.Base(ctx, id, config)
    return base
end)

Section:AddMyThing("thing", { Title = "Mine" })

build.ps1 concatenates every module into DeaDx.lua. Components are imported on demand and the icon catalog is only parsed when the first icon is asked for, so the library defines itself in a couple of milliseconds — check DeaDx.LoadTime.

Dependencies between components

One control appears, or becomes usable, only when another is in the right state — without if statements scattered through your hub.

VisibleWhen / EnabledWhen
Section:AddToggle("aimbot", { Title = "Aimbot" })

Section:AddSlider("fov", { Title = "FOV", Min = 1, Max = 400, VisibleWhen = "aimbot" })

Section:AddSegmented("mode", { Title = "Mode", Values = { "Legit", "Semi", "Rage" } })

Section:AddToggle("silent", { Title = "Silent aim", VisibleWhen = { mode = "Rage" } })

Section:AddSlider("hitchance", {
    Title = "Hit chance", Min = 0, Max = 100,
    EnabledWhen = { aimbot = true, mode = { "Rage", "Semi" } },
})

Section:AddToggle("extra", {
    Title = "Extra",
    VisibleWhen = function(options) return options.fov:GetValue() > 100 end,
})

Both accept another option's id, a table of { id = value } (where the value may be a list of accepted ones or a function), or a plain function. It re-evaluates itself whenever anything in the config changes.

Context menu

Right-click any component:

  • Copy value — the current value to the clipboard.
  • Reset to default — back to Default.
  • Set key — captures a key that then toggles or fires that control.
  • Pin to status bar — the value becomes a live field on the HUD bar. For a toggle or a button the field is clickable, so the feature can be used without opening the window at all. Pinning again unpins.

Command palette

Ctrl+K opens a search over everything: it finds any component in any tab, shows its path and current value, and uses it straight from the list — a toggle flips, a button runs, anything else scrolls into view.

palette

Guided tour

Walks a first-time user through the hub: dims everything, lights up one control at a time and explains it beside the spotlight. It changes tab and scrolls the page on its own to reach each target.

tour
Window:Tour({
    { Target = "aimbot", Title = "Aimbot", Text = "Turns the aim on. Right-click it to set a key." },
    { Target = "fov", Title = "FOV", Text = "The circle radius." },
    { Tab = "Visual", Target = "theme", Title = "Theme", Text = "Change the colours here." },
    { Target = someFrame, Title = "Anything", Text = "A GuiObject works too.", Delay = 0.4 },
}, {
    Color = "#FF2D40",
    OnFinish = function(skipped) print(skipped) end,
})

Arrows and Enter move, Esc skips. Each step takes Delay and Run (something to execute on arrival). The spotlight re-measures after the scroll settles, so the box lands exactly on the target even with animation still running.

Photos and shapes

A photo is a first-class icon. Point Icon at an avatar, a decal you uploaded or a PNG on the web and it is drawn as the photo it is — not tinted into a flat silhouette. Only the monochrome sets (the catalog, Lucide, Iconsax) take the theme colour, which is what you want from them.

The three shapes

Every icon slot in the library — window, tab, section, card, component, status bar, notification, dialog, loading screen — takes the same five fields.

FieldValuesWhat it does
IconShape"Square" "Rounded" "Circle"Sharp corners, softly rounded corners, or a full circle. Default is Square, so nothing changes until you ask for it.

Key system

Requirements render as a list with ✓ / ✗ and the reason for each failure; clicking a row re-checks it. A remembered key is stored in DeaDx/key.dat as a hash tied to the HWID (XOR against the HWID plus a derived token), so copying the file to another machine does nothing. The key text itself is never written to disk.

If you already use Luarmor, DeaDx checks the key before the protected loadstring, so a wrong key gets a message in your window instead of a kick.

What it handles for you

  • Downloads the official library.lua once and reuses it.
  • Sets the script_key global before any loadstring, the way the docs ask.
  • Turns every status code into a line in the window — KEY_EXPIRED, KEY_BANNED, KEY_HWID_LOCKED, KEY_INCORRECT, KEY_INVALID, INVALID_EXECUTOR, TIME_ERROR, UNKNOWN_ERROR.
  • Only burns an attempt when it is the user's fault. A wrong or malformed key costs an attempt; SCRIPT_ID_INCORRECT, SCRIPT_ID_INVALID, a server outage or a skewed clock do not — and the first two also warn you in the console.
  • With Remember = true, it re-validates the stored key against Luarmor on open instead of trusting the local file.
  • Stacks with the whitelist — Group, Gamepass, Wearing and the rest still apply alongside it.

Key+

In Key+ there is no return true to hook: what the server sends back is the hub itself, encrypted. Bypass the validation and there is nothing to run, because the code was never there.

The secret never reaches the client. The decryption key is derived from the key the user typed, so the script you publish holds no secret at all:

  1. The client makes a random nonce and sends key, hwid and nonce to your site.
  2. Your server validates the key however it likes — database, panel, Discord. That is where your SECRET is used, server-side only.
  3. The server answers with ts, nonce and data, where
    data = hex( XOR(script, keystream(HMAC-SHA256(user_key, "ukey|nonce|ts"))) )
  4. The client checks the ts (five minutes) and the nonce, derives the same key from what was typed, and decrypts the hub. A wrong key produces garbage and nothing runs.
key+ with the window
local key = DeaDx:CreateKeySystem({
    Title = "DeaDx",
    Plus = {
        Endpoint = "https://mysite.com/api/unlock",   -- {key} {hwid} {nonce} get filled in
        Window = 300,                                 -- how long a response stays valid
        BindHwid = false,
    },
    Remember = true,
    OnUnlock = function(source)
        loadstring(source)()      -- the real hub runs here
    end,
})
key:Wait()

If you want the response signed as well — one more layer against a fake endpoint — then pass a Secret on the client. It joins the signature and the derivation. That is optional, and only worth it if you accept that value sitting in the script:

signed mode
Plus = { Endpoint = "https://mysite.com/api/unlock", Secret = "DecodeWord" }
without the UI
local source, reason = DeaDx:KeyPlus({ Endpoint = "…" }, "USER-KEY")
if not source then return warn(reason) end
loadstring(source)()

DeaDx:KeyPlusRun({ Endpoint = "…" }, "USER-KEY")

Rejected automatically, all before anything is decrypted: wrong secret, wrong key, forged signature, swapped nonce, and a stale response (replay).

Forcing the validation gets you nowhere — flipping the internal state lets the window close, but GetPayload() stays nil, RunPayload() answers "missing payload" and OnUnlock never fires. Without a legitimate response there is no hub to run.

What Key+ still does not solve

  • Anyone with a valid key receives the hub in memory and can dump it. Key+ stops access without a key; it does not stop a leak from someone who paid. Mark the payload per key on the server and you will know whose copy leaked.
  • If your endpoint has no rate limit, keys can be brute-forced against it.
  • With Remember = true the key sits on disk scrambled with the HWID. That protects against copying the file to another machine, not against someone already on that machine.
  • The payload is only worth what is inside it. If the hub is also embedded in the script that calls Key+, none of this bought you anything.

What your Key+ server must do

the protocol
GET /api/unlock?key=<key>&hwid=<hwid>&nonce=<nonce>&v=1

1. validate <key> in your database (your SECRET is used here and NEVER leaves the server)
2. ts    = unix time now
3. skey  = HMAC_SHA256(key, "ukey|" + nonce + "|" + ts)
4. ks    = SHA256(skey + ":0") .. SHA256(skey + ":1") .. …   (raw bytes, up to the script length)
5. data  = hex(script XOR ks)
6. answer {"v":1,"ts":ts,"nonce":nonce,"data":data}

on error: {"error":"invalid key"}

In signed mode, swap key for your SECRET in step 3 (tag stream instead of ukey) and add
sig = HMAC_SHA256(SECRET, "v1|" + key + "|" + hwid + "|" + nonce + "|" + ts) to the response.

sig in lowercase hex. data accepts hex or base64. The script may start with --DEADX so the client can recognise the content without compiling it. With BindHwid = true the hwid enters the derivation too.

testing with no server at all
local cfg = { Endpoint = "https://x" }

    cfg, "KEY", DeaDx:GetHwid(), nil, os.time(), "--DEADX\nprint('ok')"

FAQ

Does it work on mobile?

Yes, and that is not an afterthought — every control is touch-tested. The window drags from the top bar, sliders track a finger, dropdowns scroll, and the status bar can sit above the hotbar where a thumb reaches it.

What does it need from the executor?

Nothing mandatory. Capabilities probes for file access, getcustomasset, gethui, HTTP and the integrity functions, and degrades instead of erroring. No file access means icons are not cached and configs stay in memory; everything else carries on.

Can I load it twice?

Yes. The second load unloads the first, so nothing is left behind.

How do I keep users on my theme?

LockTheme and LockScale on the window, or DeaDx:LockTheme(name) at any point. The theme editor then refuses to change it.

Which protection should I use?

Key system for a gate that is easy to run yourself. Luarmor if you already pay for it and want key distribution handled. Key+ if it actually matters that people without a key cannot get the code — it is the only one where the hub is not on their machine until your server says so.
